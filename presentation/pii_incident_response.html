🚨 PII Incident Response & Prevention

Scenario: A user accidentally accessed PII data they shouldn't have

SECTION 1: Reasons for PII Leak

How Could This Happen?

📊
1. Schema Drift (Without Rescue Mode)
New PHI field added by source system. Without rescue mode, Auto Loader's default "addNewColumns" auto-ingests to Bronze unmasked with no alert. Sits undetected for weeks.
🔓
2. Incorrect RBAC
Bronze table granted to broad groups (50+ users). No Unity Catalog access controls configured. Relying on "trust" instead of technical controls.
🎭
3. No Column Masking
PHI flows to Silver unmasked. Analysts granted Silver access for "joins". Result: 20+ analysts see raw patient_id, provider_id.
👁️
4. Materialized View Exposure
Admin creates materialized view from Bronze with raw PHI. Grants access to analysts. Users query the copy, bypassing Bronze permissions.

⚠️ The Common Thread

All four scenarios share the same root cause: Reactive security posture instead of proactive prevention. We discover issues during audits (months later) rather than preventing them at ingestion (minutes).

SECTION 3: Investigation - Accessing Audit Logs

Step 1: Query Unity Catalog Audit Logs

🔍 Identify Unauthorized Access
-- Query system.access.audit to find who accessed Bronze
SELECT 
    event_time,
    user_identity.email AS user_email,
    request_params.full_name_arg AS table_accessed,
    action_name,
    request_params.command_text AS query_executed,
    request_params.operation_result AS result
FROM system.access.audit
WHERE event_date >= current_date() - INTERVAL 7 DAYS
  AND request_params.full_name_arg LIKE '%bronze%'
  AND user_identity.email NOT IN (
      -- Authorized Bronze users
      'compliance-lead@company.com',
      'compliance-analyst@company.com',
      'de-lead@company.com'
  )
ORDER BY event_time DESC
LIMIT 100;

    -- Count how many queries they ran

    MIN(event_time) as first_access,

FROM system.access.audit
WHERE user_identity.email = 'analyst@company.com'
  AND request_params.full_name_arg LIKE '%bronze%'
  AND event_date >= current_date() - INTERVAL 30 DAYS
GROUP BY user_identity.email, request_params.command_text
ORDER BY first_access DESC;

SECTION 4: Immediate Steps (Within 1 Hour)

Containment Actions

1
Revoke Access Immediately
Remove Bronze access from 'data_analysts' group. User loses access within seconds.
REVOKE SELECT ON SCHEMA healthcare.bronze FROM `data_analysts`;
2
Notify User & Manager
Email user and their manager about PHI access incident. Request deletion of any saved queries, notebooks, or CSV exports.
3
Document Incident
Create compliance incident record with timeline, scope, and containment actions taken.
INSERT INTO healthcare.compliance.incident_log VALUES ( current_timestamp(), 'analyst@company.com', 'healthcare.bronze.claims_837', 'Unauthorized access to raw PHI - 100 records', 'High', 'Contained - Access revoked, user notified' );
4
Review All Group Memberships
Query Azure AD to verify no other junior analysts have Bronze access via other groups.
SHOW GRANTS ON SCHEMA healthcare.bronze;
SECTION 5: Prevention & Data Deletion in Databricks

Fix Root Causes & Clean Up

🛡️
1. Harden RBAC
Restrict Bronze access to 5-8 authorized users only. Remove broad group permissions.
Actions:
  • Audit all Bronze table GRANTs
  • Remove 'data_analysts' group
  • Only grant to 'compliance-team'
  • Implement quarterly access reviews
🔐
2. Implement Column Masking
Create masked views for analysts who need Silver access for joins.
Actions:
  • Apply SHA256 masking at Silver layer
  • Create dynamic masking views
  • Grant analysts access to views only
  • Test: Users see hashed PHI, not raw
📊
3. Rescue Mode Schema Control
Use Auto Loader's "rescue" mode to quarantine new columns in _rescued_data instead of auto-adding them.
Actions:
  • Set cloudFiles.schemaEvolutionMode = "rescue"
  • Monitor _rescued_data column for non-null values
  • Alert on schema drift within 15 min
  • Review new fields before adding to schema
🚨
4. Real-Time Monitoring
Alert on any Bronze access by non-compliance users immediately.
Actions:
  • Query system.access.audit every 15 min
  • Flag unauthorized Bronze access
  • Send alert to security team
  • Automatic incident ticket creation

Data Deletion in Databricks (If Required)

🗑️ Delete Exposed Records from All Layers
-- Step 1: Soft delete (immediate) - Mark as REDACTED
UPDATE healthcare.bronze.claims_837
SET 
    patient_id = 'REDACTED',
    provider_id = 'REDACTED',
    _deletion_timestamp = current_timestamp(),
    _deletion_reason = 'Unauthorized access incident'
WHERE claim_id IN (
    -- IDs accessed by unauthorized user
    SELECT DISTINCT claim_id FROM exposed_records_log
);

-- Step 2: Delete from Silver (masked data)
DELETE FROM healthcare.silver.claims_837
WHERE claim_id IN (SELECT claim_id FROM exposed_records_log);

-- Step 3: Re-aggregate Gold (automatically updates)
REFRESH MATERIALIZED VIEW healthcare.gold.provider_performance;

-- Step 4: Hard delete after 30 days (physically remove from Delta)
VACUUM healthcare.bronze.claims_837 RETAIN 30 HOURS;
VACUUM healthcare.silver.claims_837 RETAIN 30 HOURS;

⚠️ Delta Time Travel Consideration

Important: Even after DELETE, historical versions exist in Delta Lake. VACUUM physically removes them, but you lose time-travel capability. Balance compliance requirements (immediate deletion) with audit requirements (retain history for 30 days).

SECTION 6: Long-Term Solution (Architecture Changes)

Proactive Prevention Architecture

🎯 Enterprise-Grade Security Model

🔐 Unity Catalog RBAC

Integrate with Azure AD via SCIM. Groups managed in Azure AD automatically sync to Databricks. Single source of truth for access control.

🛡️ Rescue Mode Schema Control

Auto Loader configured with "rescue" mode. New PHI fields automatically quarantined in _rescued_data with 15-minute alerts. Zero-config schema drift protection.

🎭 Dynamic Masking

Unity Catalog column-level masking. Analysts see masked PHI automatically based on group membership. No separate views needed.

📊 Real-Time Monitoring

Automated queries of system.access.audit every 15 minutes. Alerts fire immediately on unauthorized access. 1-hour incident response SLA.

🔍 Quarterly Access Reviews

Automated report of all Bronze access grants. Manager approval required for any changes. Stale permissions auto-expire after 90 days.

📝 Compliance Automation

Automatic incident logging, deletion tracking, and audit certificate generation. HIPAA-ready reporting with complete lineage.
